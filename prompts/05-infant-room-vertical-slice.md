# 05. 영유아 방 — 1차 수직 시연

## 목표

스펙 9.1 "수직 시연 1차"를 완성한다: 영유아 방 1개, 가구 9개(표에는 8개 + 북측 보조 태블릿 1개 = 총 9개 상호작용 지점), 자유 이동/충돌 회피, 도구 반응, 수치, 1회 효과, 복도 페이드까지 — 처음부터 끝까지 플레이 가능한 세로 슬라이스. 이 프롬프트가 끝나면 "관찰만 해도 2개 이상 물품을 경험하고 끝까지 진행"하는 완전한 루프가 동작해야 한다.

## 선행 조건

03-room-shell-and-navmesh.md, 04-tool-and-stress-model.md 완료. (06-corridor-transition-system.md은 아직 없어도 된다 — 이번 프롬프트에서는 "복도로 넘어가는 페이드"까지만 최소로 구현하고, 복도 자체의 완전한 연출은 06번에서 확장한다.)

## 참고 스펙 섹션

`docs/spec.md` 2.1(시간 진행 규칙), 5.1(프롤로그, 참고만), 5.2(영유아기 — 첫 손길) 전체.

## 구현 지시사항

1. **`ItemDefinition` ScriptableObject:** 필드 — `itemId`, `displayName`, `tags`(string[], 예: "공부", "놀이", "창작" 등 4.3의 태그 목록), `statDeltas`(StatType별 float, S/I/H/P/L), `isExtreme`(★ 여부, 05번에서는 전부 false), `narrativeLines`(서사 대사 텍스트, placeholder 문자열로 충분).
2. 5.2 표의 9개 물품(알파벳 그림책, 감각 블록, 조기학습 화면, 포옹 의자, 친구 곁 공놀이, 달콤한 간식 상자, 혼자 기어가기 길, 작은 침대, 유튜브 태블릿)을 `ItemDefinition` 에셋으로 각각 만들고, 03번의 `ItemSlot` 좌표(북서/북중/북동/남서/남중/남동/동측/서측/북측 보조)에 정확히 매칭해 배치한다.
3. **`ItemEffectApplier` (순수 C# 클래스):** `ItemSlot.OnFirstVisit`이 호출되면 해당 `ItemDefinition.statDeltas`를 `StatSystem.ApplyDelta`로 각 스탯에 적용한다. 일반 물품은 한 번 적용 시 각 수치 최대 ±12 제한(4.4) — 05번 물품들은 표의 수치가 모두 이 범위 안이므로 지금은 clamp만 안전장치로 넣어 두고, ★ 물품의 ±25 허용은 09번 이후에서 다룬다. 재방문 시에는 `ItemDefinition.narrativeLines`의 다른 줄만 재생하고 수치는 절대 다시 적용하지 않는다(ItemSlot이 이미 첫 방문 여부를 추적하므로 여기서 다시 검증).
4. **개입 쿨다운 (4.2 마지막 문단):** 방 진입 후 초반 90초 동안은 도구 사용을 비활성화(또는 사용은 가능하지만 물리적 밀림 효과가 없도록)하여 아이가 자유 선택한 물품 2개 이상이 반드시 기록되게 한다. 이 쿨다운은 `GameBalanceConfig.toolCooldownOnRoomEnterSeconds` 필드로 관리하고 UI에 남은 시간을 간단히 표시한다(튜토리얼 성격 — "잠시 지켜봐 주세요" 같은 placeholder 텍스트로 충분).
5. **시간 진행 (2.1):** 방 진입 후 8분 기준으로 창가 빛 이동(간단한 Directional Light 회전 또는 색온도 변화로 placeholder), 문이 서서히 가까워지는 느낌은 지금 단계에서는 "문 앞 조명이 켜지는" 정도의 최소 연출로 충분하다. 7분 이전에는 문이 열리지 않고(출구 콜라이더 비활성 또는 상호작용 불가), 8분 도달 시 문이 열리며 초파리가 스스로 출구 쪽으로 이동 확률이 올라가도록 `PickNextDestination`에 "출구 근처 지점"을 후보에 추가한다. 10분 경과 시 모든 `ItemSlot`의 효과 적용을 멈춘다(이미 방문한 건 유지, 새 효과만 중단).
6. **방 종료 트리거:** 04번에서 만든 휠체어 로코모션으로 플레이어가 직접 왼손 스틱을 조작해 동쪽 출구 경계(콜라이더/트리거 볼륨)에 도착하면 0.5초 이상의 페이드 아웃 후 다음 씬/상태로 전환한다(시선 레이캐스트나 UI 버튼 트리거는 쓰지 않는다 — 스펙 2.1/8장). 지금은 복도의 완전한 구현이 없으므로, 페이드 후 간단한 "복도 placeholder" 빈 공간(검은 화면 + "복도" 텍스트)으로만 넘어가도 된다 — 06번에서 이 자리를 실제 복도로 교체하고, 그 복도도 휠체어로 직접 운전해서 통과하게 한다.
7. 저장 체크포인트(02번 `SaveSystem.SaveCheckpoint`)를 "방 진입", "각 물품 최초 방문", "복도 시작" 시점에 호출한다.

## 완료 조건 (Acceptance Criteria)

- [x] 방에 입장해서 아무 입력도 하지 않아도(순수 관찰) 8~10분 안에 최소 2개 이상의 물품이 자율적으로 방문되고, 시간이 다 되면 출구가 열리고 다음 단계로 진행된다.
- [x] 9개 물품 모두 최초 방문 시 정확히 표의 S/I/H/P/L 값이 적용되고, 재방문 시 수치가 다시 적용되지 않는다(로그로 확인).
- [x] 태블릿(북측 보조)과 다른 물품 사이를 오갈 때 이동이 막히지 않는다(9.6 "영유아기 태블릿 추가 검증"의 선행 확인 — 완전한 검증은 16번에서 자동화).
- [x] 초반 90초 동안 도구를 써도 초파리가 물리적으로 밀리지 않는다(쿨다운 적용 확인).
- [x] 7분 이전에는 출구가 열리지 않고, 8분 경과 후 열리며, 10분 경과 후 새 물품 효과가 더 이상 적용되지 않는다(시간 가속 디버그 기능으로 빠르게 확인 — 8분을 실제로 기다리지 않도록 `GameBalanceConfig`에 디버그용 시간 배속 필드를 추가해도 된다).
- [x] 방 종료 시 페이드가 0.5초 이상이며 급격한 카메라 전환이 없다(8장 편안함 기준의 선행 적용).
- [x] 전체 흐름(입장 → 자유 관찰/개입 → 출구 → 페이드 → 다음 단계 placeholder)이 에러 없이 한 번에 끝까지 재생된다.

2026-11-23 Unity 자동 검증 완료: 전체 EditMode 65/65, PlayMode 21/21 통과(실패·생략 0). 첫 항목의 무입력 진행은 출구 개방까지이며, 복도 전환은 명세 2.1과 위 지시사항 6에 따라 왼손으로 직접 출구를 통과해 검증했다. 실제 HMD의 양안 페이드와 착용감은 별도 확인이 필요하다. [실측 시간·9개 최초 방문 로그·수정 내역](../docs/tech-stack.md#05-검증-상태)을 참고한다.
