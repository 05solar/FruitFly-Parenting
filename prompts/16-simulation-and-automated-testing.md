# 16. 자동 시뮬레이션 러너와 9장 전체 검증

## 목표

사람이 VR 헤드셋을 쓰고 반복 플레이하는 것으로는 현실적으로 다 확인할 수 없는 조합(수백~수천 회의 서로 다른 개입 패턴 × 14개 엔딩 × 각종 경계값)을 **헤드셋 없이, 렌더링 없이, 헤드리스로 수천 회 자동 실행**해서 검증하는 시뮬레이션 러너를 만든다. 스펙 9.4~9.8의 "필수 시나리오 검사" 전체를 이 러너로 자동화한다.

## 선행 조건

12-middleage-and-endings.md 완료 (전체 루프 완결). 이 프롬프트는 02~12번에서 모든 게임플레이 로직을 "순수 C# 클래스 + MonoBehaviour 어댑터"로 분리해 둔 설계 원칙(tech-stack.md 4장)에 의존한다 — 만약 이 분리가 지켜지지 않은 부분이 발견되면, 이 프롬프트 안에서 먼저 그 부분을 리팩터링한다.

## 참고 스펙 섹션

`docs/spec.md` 9.4~9.8(필수 시나리오 검사 전체), 그리고 이 검사들이 참조하는 4.2~4.6, 6장.

## 구현 지시사항

1. **`SimulationRunner` (순수 C# 클래스, Unity 씬 의존 없음):** 02~12번에서 만든 순수 로직 클래스(`StatSystem`, `RelationshipState`, `PushResolver`, `ComplianceStateMachine`, `ItemChoiceModel`, `EndingEvaluator` 등)만 가져와서 **렌더링/NavMesh/XR 없이** 한 회차 전체를 시뮬레이션한다.
   - 초파리의 NavMesh 이동은 시뮬레이션에서 "어떤 아이템으로 이동 중/도착함"이라는 이산 이벤트로 추상화한다(실제 좌표 이동 없이 `ItemChoiceModel`이 고른 다음 목적지에 "도착했다"고 바로 처리). 이동 중 걸리는 시간은 거리 기반으로 근사 계산해 4.2의 "30초 이상 머물면 이동" 같은 시간 규칙이 여전히 의미를 가지게 한다.
   - "가상 플레이어"가 도구를 사용하는 패턴은 `IPlayerPolicy` 인터페이스로 추상화하고 최소 다음 구현체를 만든다: `PassivePolicy`(전혀 개입 안 함), `RandomInterventionPolicy`(무작위 빈도/강도로 개입), `AggressiveCoercionPolicy`(특정 태그 쪽으로 지속적으로 강하게 밀어서 7번의 순응을 의도적으로 유발), `TargetedEndingPolicy`(특정 엔딩을 의도적으로 노리는 개입 패턴 — 14개 엔딩 각각에 대해 하나씩 만들 수 있으면 가장 좋다).
2. **대량 실행:** 각 `IPlayerPolicy` × 여러 `RunSeed`(예: 1,000개 이상)로 전체 회차(프롤로그~엔딩)를 시뮬레이션하고, 각 실행의 결과(최종 스탯, 플래그, 채택된 엔딩, 전체 이벤트 로그)를 수집한다. 이 실행은 Unity Test Framework의 PlayMode/EditMode 테스트가 아니라 별도의 커맨드/에디터 메뉴 도구(`Assets/_Project/Scripts/Debug/SimulationRunnerMenu.cs`, Unity 에디터 메뉴 항목으로 실행)로 만들어 수천 회를 몇 분 안에 끝낼 수 있게 한다.
3. **9.4 필수 시나리오 검사를 자동화:**
   - 벽/물품 끼임 없음 → 시뮬레이션에서는 좌표 이동이 추상화되어 있으므로 이 항목은 **PlayMode 테스트**(실제 NavMesh 사용)로 별도 보완한다: 각 방에서 FlyAgent를 수 분간 자동 조작(랜덤 입력 fuzzing)해 `NavMeshAgent.isOnOffMeshLink`/충돌 이벤트/정지 좌표가 벽 내부인지 등을 체크.
   - 반복 도구로 스트레스 증가폭 상승 → `RandomInterventionPolicy`로 짧은 간격 연속 사용 시 04번 공식대로 증가폭이 커지는지 수천 회 샘플에서 일관되게 확인.
   - 반응 중 추가 밀기 차단(= 04번 "혼자 해볼래" 12초 회피 중 접촉 무시) → 해당 상태 동안 들어온 `ToolUsed` 입력이 실제로 무시되는지.
   - 물품 효과 중복 없음 → 모든 시뮬레이션 실행에서 같은 `itemId`에 대한 효과 적용 이벤트가 회차당 최대 1회인지 전수 검사.
   - **14개 엔딩 모두 도달 가능** → `TargetedEndingPolicy` 14종 각각이 의도한 엔딩을 실제로 만들어내는지 확인(12번의 EditMode 테스트가 "조건→엔딩" 단위 테스트였다면, 이건 "실제 플레이 패턴→조건 충족→엔딩"이 자연스럽게 이어지는지의 통합 검증).
   - 히든 의상과 엔딩 각각 도달 가능 → 동일한 방식으로 확인.
   - 모든 수치 경계 0~100 → 1,000회 이상의 무작위 정책(특히 `AggressiveCoercionPolicy`처럼 극단적으로 수치를 밀어붙이는 정책) 실행 전체에서 한 번도 범위를 벗어나지 않는지 어서션.
   - 청소년 의상 조건 검사 → 10번 `CostumeEvaluator`를 다양한 S 조합으로 fuzzing.
   - 엔딩 카드의 실제 방문 로그 일치 → 시뮬레이션 결과의 "결정적 경험 3개"가 로그에서 실제로 유도 가능한지.
   - 초기 값과 물품 효과만으로 L=100이 가능한지 → `PassivePolicy`(개입 없음)로도 L=100에 도달하는 시드가 존재하는지 전수 탐색, 존재한다면 마법소녀 엔딩(조건에 L=100 포함)의 도달 가능성과 연결해 보고.
4. **9.5~9.8의 세부 검증도 같은 러너로 자동화:**
   - 9.5 도박 엔딩: `도박파산` 플래그가 다른 조건보다 항상 먼저 채택되는지, 도박장 미방문 시드에서는 해당 엔딩이 전혀 나오지 않는지.
   - 9.6 영유아 태블릿: 북측 보조 슬롯 이동 차단 없음, 첫 방문만 효과, 아동기 소비·놀이 선호 반영.
   - 9.7 강제/반복 훈련: 약한/강한 밀기 R/S 증가 정확성, 방문당 1회 추가 효과, 3개째부터 반복 훈련, R=59/60 경계의 비행·흡연 이벤트.
   - 9.8 순응: R=100에서도 8점 누적 시 순응, 방향 전환/10초 경과 시 리셋, 조폭 엔딩이 R만으로는 안 나오고 비행기록·플래그·P·T 전부 필요함을 수천 회 샘플에서 반례 없이 확인.
5. **결과 리포트 출력:** 시뮬레이션 결과를 `Assets/../SimulationReports/`(Git에는 커밋하지 않도록 `.gitignore`에 추가) 아래 CSV/JSON으로 저장해, 엔딩별 도달 빈도, 평균 최종 수치, 위반 사례(있다면) 목록을 사람이 읽을 수 있게 정리한다.
6. **재현성 검증:** 같은 `RunSeed` + 같은 `IPlayerPolicy` 설정으로 같은 결과(동일 엔딩, 동일 최종 수치)가 나오는지 확인한다(8장 "회차마다 난수 시드와 이벤트 로그를 저장해 재현 가능하게 한다"의 핵심 검증).

## 완료 조건 (Acceptance Criteria)

- [ ] `SimulationRunnerMenu`로 1,000회 이상의 시뮬레이션이 Unity 씬 로드 없이 몇 분 안에 끝난다.
- [ ] 9.4~9.8의 모든 검사 항목이 자동화된 테스트/시뮬레이션 어서션으로 커버되고 전부 통과한다(실패하는 항목이 있으면 이 프롬프트를 끝내지 않고 원인이 된 01~12번의 로직을 고친 뒤 재실행한다).
- [ ] 14개 엔딩 전부가 최소 1개 이상의 시드/정책 조합으로 실제 도달이 확인된다.
- [ ] 수치 경계 위반이 0건이다.
- [ ] 동일 시드+정책 재실행 시 100% 동일한 결과가 나온다.
- [ ] 벽/물품 끼임에 대한 PlayMode fuzz 테스트가 각 방(05, 09, 10, 11, 12)에서 최소 5분 분량 실행되고 이상 없음을 확인한다.

## 보고

시뮬레이션 실행 횟수와 소요 시간, 엔딩별 도달 빈도표, 발견해서 고친 버그 목록(있다면 어떤 프롬프트의 로직이었는지 명시), 최종적으로 9장 전체 체크리스트가 모두 녹색인지 보고한다.
