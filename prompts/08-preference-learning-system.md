# 08. 태그 선호/회피 학습 시스템

## 목표

스펙 4.2~4.3의 "학습 이벤트"와 "선택 확률(softmax)"을 구현해, 초파리의 자율 이동이 03번의 순수 랜덤에서 실제 경험 기반 선택으로 진화하게 한다. 이 시스템은 이후 모든 방(09~11)에서 "이전 방에서 뭘 겪었느냐가 다음 방 선택에 영향을 준다"는 핵심 약속을 지키는 토대다.

## 참고 스펙 섹션

`docs/spec.md` 4.2(초파리 자율 이동), 4.3(학습 이벤트, 선택 확률의 초안) 전체.

## 구현 지시사항

1. **태그 체계 정리:** 전체 태그 목록을 한 곳(`TagDefinitions` 정적 클래스 또는 enum)에 고정: 놀이, 공부, 휴식, 운동, 관계, 성과, 소비, 창작, 반항. `ItemDefinition.tags`(04/05번에서 이미 string[]였던 것)를 이 enum 배열로 교체하거나 문자열을 이 목록으로만 제한하는 검증을 추가한다.
2. **`PreferenceMemory` (순수 C# 클래스, 회차 전체에 걸쳐 유지 — `GameState`가 보관):**
   - 태그별 "선호 가중치"(float, 초기 0)와 "회피 기억"(float, 초기 0)을 딕셔너리로 관리.
   - **학습 이벤트 A — 저지 학습(회피/신뢰):** 물품에 다가가기 전 6초 안에 도구 개입(밀기)이 있었고 실제로 방향이 바뀌었을 때, `(room, itemTag, approachDirection, interventionCount, stress, outcome)`을 기록하고 해당 태그의 "회피 기억"을 증가시킨다. "방향이 바뀌었다"는 03번 `PickNextDestination`이 원래 잡았던 목적지와 실제 도착 지점이 달라졌는지로 판정한다.
   - **학습 이벤트 B — 선호 학습(즐거움/피로):** 물품 방문 후 그 물품의 스탯 효과가 긍정적(S 감소 또는 I/H/P/L 증가가 우세)이었는지를 간단한 가중합으로 판정해 해당 태그의 "선호 가중치"를 조정한다.
   - 방을 넘어갈 때 물품 이름(itemId)이 아니라 태그 단위로 일반화해서 유지한다(예: 장난감 앞에서 자주 막혔다 → "놀이" 태그 회피 기억 증가 → 다음 방의 "놀이" 태그 물품을 덜 먼저 찾음). **완전 접근 금지는 절대 만들지 않는다** — 회피 기억이 아무리 높아도 선택 확률이 0이 되지 않도록 아래 softmax에 하한을 둔다.
3. **선택 확률 모델 (`ItemChoiceModel`, 순수 C# 클래스):**
   ```
   score(item) = baseAttraction(item) + tagPreference(item.tags) - avoidanceMemory(item.tags) + stateNeed(item, currentStats) + smallRandomNoise
   P(item) = softmax(score) over all currently reachable items
   ```
   - `baseAttraction`: `ItemDefinition`에 필드 추가(기본값은 모든 물품 동일하게 둬도 됨, 추후 밸런스 패스에서 조정).
   - `stateNeed`: 예를 들어 스트레스가 높으면 휴식 태그 물품의 score가 올라가는 식의 간단한 보정(구체적 공식은 스펙에 없으므로 합리적으로 설계하고 근거를 보고서에 남긴다 — 과도하게 복잡하게 만들지 않는다).
   - 난수 탐색 비율 하한을 방 시기별로 적용: 영유아 0.65, 아동 0.55, 청소년 0.45, 청년 0.35. 구현 방법: `P_final(item) = (1 - explorationFloor) * softmax(score) + explorationFloor * uniform` 형태로, 강한 편향이 있어도 모든 물품이 최소한의 확률을 유지하게 한다. 이 하한 값들은 `GameBalanceConfig`에 방 시기별 필드로 노출.
4. **03번 `PickNextDestination`과의 통합:** 03번에서는 100% 균등 랜덤이었던 부분을 이제 `ItemChoiceModel.ChooseNextItem()`으로 교체한다. "같은 물품 연속 2회 금지", "30초 초과 체류 시 강제 이동" 같은 기존 제약은 그대로 유지하고, 그 제약을 통과한 후보들 중에서만 softmax를 적용한다.
5. **디버그 패널 (`DebugHud`, UI 오버레이):** 현재 목적지, 선택 이유(각 후보의 score 분해값), 사용된 난수 시드를 화면에 표시한다. 에디터/개발 빌드에서만 보이도록 토글(예: 키보드 단축키 또는 빌드 심볼)로 켜고 끈다.
6. EditMode 테스트:
   - 같은 태그에 회피 기억이 아무리 커져도(예: 1000으로 강제 설정) 해당 태그 물품의 최종 선택 확률이 0이 되지 않는지(explorationFloor 하한 검증).
   - softmax 계산이 score가 동일한 후보들에 대해 균등 확률을 주는지(기본 성질 검증).
   - 학습 이벤트 A/B가 올바른 조건에서만 트리거되는지(6초 윈도, 방향 변경 여부).
   - 시기별 explorationFloor 값이 `GameBalanceConfig`에서 올바르게 읽히는지.
