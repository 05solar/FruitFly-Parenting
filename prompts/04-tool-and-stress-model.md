# 04. 전기 휠체어, 사랑의 매와 스트레스 모델

## 목표

플레이어가 타는 전기 휠체어(왼손 스틱으로 이동)와 오른손에 항상 장착된 전기 사랑의 매, 그리고 이 둘의 접촉으로 발생하는 기본 스트레스/신뢰 공식을 구현한다. 이 단계는 아직 4.5(강제/반복 훈련)와 4.6(순응)을 포함하지 않는다 — 그건 07번에서 이 위에 쌓는다. 지금은 "휠체어의 약한 밀기와 전기 봉의 강한 밀기가 초파리를 물리적으로 밀어내고, 접촉 빈도에 따라 스트레스가 비선형으로 쌓인다"까지만 구현한다.

## 선행 조건

02-core-data-architecture.md, 03-room-shell-and-navmesh.md 완료. 01번에서 임포트해 둔 XRI Locomotion System 샘플이 필요하다.

## 참고 스펙 섹션

`docs/spec.md` 4.3(전기 휠체어와 사랑의 매의 방향 유도) 전체, 2.2(표준 방 규격 — 휠체어 폭/회전 여유), 8장("이동과 손 배치" 선행 적용).

## 구현 지시사항

1. **`WheelchairRig` 프리팹:** XR Origin을 자식으로 포함하는 휠체어 리그. 캡슐/박스 콜라이더로 휠체어 몸체(폭 0.8m)를 표현하고, 앞쪽에 별도의 작은 트리거 콜라이더("범퍼")를 붙인다. 01번에서 임시로 배치했던 XR Origin을 이 리그의 자식으로 재배치한다.
2. **`WheelchairLocomotion` (MonoBehaviour):** 왼손 컨트롤러 스틱 입력만 받아 XRI의 Continuous Move/Turn Provider를 구동한다. 플레이어는 03번에서 만든 NavMesh를 쓰지 않는다(그 NavMesh는 초파리 전용) — 휠체어는 자유로운 연속 이동 + 콜라이더 충돌로만 움직인다. 가속/감속/최고속도/회전속도를 `GameBalanceConfig`에 필드로 노출하고 지금은 낮은 기본값으로 설정한다(세부 튜닝은 14번에서 다룸 — 지금은 "급가속/급회전이 없다"는 정도만 지킨다).
3. **`WheelchairBumperPushResolver` (순수 판정 로직 + 범퍼 트리거 MonoBehaviour 어댑터):** 범퍼 콜라이더가 `FlyAgent`와 겹쳤을 때만 호출된다.
   - 휠체어가 정지해 있거나(속도 ≈ 0, 임계값은 `GameBalanceConfig.wheelchairMinSpeedForPush`) 초파리와 접촉하지 않으면 밀기 이벤트가 발생하지 않는다.
   - 접촉 시 초파리는 "휠체어 진행 방향"으로 약하게 밀린다(기존 스펙의 '전기 없는 사랑의 매 1회'와 동일한 수준의 임펄스 — `GameBalanceConfig.wheelchairPushForce`).
   - 접촉 후 다음 밀기는 최소 1초 간격으로만 판정(`GameBalanceConfig.wheelchairPushCooldownSeconds`).
   - 범퍼가 벽/가구와 초파리 사이에 끼이지 않도록, 밀어내는 목적지는 항상 "안전한 NavMesh 지점"(03번 NavMesh 질의로 가장 가까운 유효 지점)으로 계산한다.
4. **`LoveStickTool` (MonoBehaviour):** 오른손 컨트롤러의 자식으로 항상 고정 장착되는 경광봉이다(그랩/해제 없음 — 손에서 쥐었다 놓는 XRI 인터랙션이 아니라 처음부터 오른손에 붙어 있는 오브젝트). 버튼 입력을 받지 않는다. 봉 끝 콜라이더가 `FlyAgent`와 겹치면 **항상** "강한 밀기 + 감전 연출"이 발생한다.
5. **`PushResolver` (순수 C# 클래스, 공용):** `PushSource` enum(`Wheelchair`, `ElectricStick`) 두 입력 소스를 받는 단일 클래스로 통합한다. 입력 = (접촉 방향 벡터, `PushSource`, 현재 초파리 위치/이동 상태). 출력 = 밀어낼 방향(접촉 방향의 반대)과 힘의 크기. `Wheelchair`면 `wheelchairPushForce`, `ElectricStick`이면 `strongPushForce`(스펙상 종전 "강한 밀기"와 동일 크기) 적용 + `ElectricStick`인 경우에만 `EventBus.ElectricShockVisual` 발행. 이 클래스는 Unity Transform에 의존하지 않고 방향을 `Vector2`/`Vector3`로 순수하게 계산해 EditMode 테스트가 가능해야 한다.
6. **밀림이 초파리 이동에 미치는 효과:** `FlyAgent`가 `PushResolver`의 출력을 받으면 NavMeshAgent에 밀려난 지점으로 이동을 적용한다. 밀려난 뒤에는 03번 `PickNextDestination`이 정상적으로 재개된다(밀기는 "일시적 외력"). 초파리가 `ItemSlot`과 상호작용 중이었다면 휠체어의 약한 밀기든 스틱의 강한 밀기든 그 반경 밖으로 밀어낼 수 있지만, 아이는 자유 행동으로 다시 돌아갈 수 있다(= 강제 금지 아님, 거리만 벌림 — 영구 차단은 07번의 "반감 학습"에서 확률적으로만 다룸).
7. **개입(=접촉) 공용 집계:** `ToolUsageTracker` (순수 C# 클래스)는 휠체어의 유효한 약한 밀기와 전기 봉의 유효한 접촉을 **모두 1회 개입으로** 합산해 최근 60초 타임스탬프 리스트에 기록한다(스펙 4.3 "개입 스트레스" 문단 — 소스가 다르더라도 개입 횟수 n은 공유). 매 접촉마다:
   ```
   n = 직전 60초 동안의 개입 횟수(이번 접촉 포함 이전 것들, 소스 무관 합산)
   delta = min(3.0, 0.4 + 0.25 * max(0, n - 2))
   StatSystem.ApplyDelta(Stress, delta, "contact_base")
   ```
   - 접촉 소스가 `ElectricStick`이면 위 delta에 **더해서** 즉시 `StatSystem.ApplyDelta(Stress, 2, "electric_stick_immediate")`를 추가 적용한다(스펙 4.3 "전기 봉의 각 접촉에는 4.5의 S +2가 추가된다" — 4.5의 강제 훈련 여부와 무관하게 접촉 자체에 항상 붙는 항이다. 07번에서 강제 훈련 추가 효과를 쌓을 때 이 항과 중복되지 않도록 설계가 분리되어 있음을 코드 주석으로 남긴다). 휠체어 접촉에는 이 추가항이 없다.
   - 60초 윈도 계산은 02번에서 만든 가짜 시간 주입 패턴을 그대로 따른다(실시간 `Time.time`이 아니라 전달받은 `currentTime`).
8. **신뢰 T 공식 (4.3):**
   - 직전 접촉(소스 무관)과의 간격이 5초 미만이면 `RelationshipState.AdjustTrust(-1, "rapid_repeat")`.
   - 접촉 없이 60초가 지날 때마다 `AdjustTrust(+1, "left_alone")`, 방당 누적 최대 +4(방 진입 시 리셋).
9. **"잠깐 혼자 해볼래" 반응:** 연속 4회 접촉(소스 무관, 휠체어+전기 봉 합산) 시 초파리가 12초 동안 접촉을 무시하고 기존 목표로 이동을 계속한다. `FlyMoodState`(03번에서 자리를 마련해 둔 상태머신 — 없다면 지금 작은 enum/상태 클래스로 추가)의 한 상태로 구현하고, 07번에서 순응 임계점 도달 시 즉시 종료할 수 있는 `ForceEndAvoidance()` 메서드를 지금 만들어 둔다.
10. EditMode 테스트 (`Assets/Tests/EditMode/WheelchairAndStickModelTests.cs`):
    - 정지한 휠체어가 초파리와 겹쳐도 밀기 이벤트가 발생하지 않는지.
    - 이동 중인 휠체어의 범퍼 접촉만 약한 밀기를 발생시키는지, 접촉 후 1초 안의 재접촉이 무시되는지.
    - 전기 봉 접촉은 항상(휠체어 이동 상태와 무관) 강한 밀기 + 감전 연출을 발생시키는지.
    - 휠체어 밀기와 전기 봉 밀기의 임펄스 강도가 다른지(전기 봉 > 휠체어).
    - 접촉 소스별 개입 횟수 n이 공유 합산되는지(휠체어 2회 + 전기 봉 1회 = n이 3을 반영).
    - 전기 봉 접촉마다 기본 공식 delta에 +2가 항상 추가되는지, 휠체어 접촉에는 이 +2가 없는지.
    - 60초가 지난 과거 접촉은 n 계산에서 제외되는지.
    - 5초 미만 간격 반복 시 T가 -1 되는지, 60초 무접촉마다 T가 +1씩 방당 +4에서 멈추는지.
    - 연속 4회 접촉 후 회피 상태로 전환되는지, `ForceEndAvoidance()` 호출 시 즉시 종료되는지.

## 완료 조건 (Acceptance Criteria)

- [ ] 위 EditMode 테스트가 모두 통과한다.
- [ ] `03_RoomShellTest` 씬에서 왼손 스틱으로 휠체어를 몰아 범퍼로 초파리에 닿으면 약하게 밀려나는 것이 보이고, 정지 상태에서 접촉해도 밀리지 않는다.
- [ ] 오른손의 전기 봉 끝을 초파리에 대면 항상(별도 버튼 입력 없이) 강하게 밀리며 감전 연출(placeholder)이 재생된다.
- [ ] 초파리가 아이템과 상호작용 중일 때 휠체어로 밀어내면 다시 자유 이동으로 그 아이템에 돌아갈 수 있다(수동 확인).
- [ ] 왼손 입력은 오직 휠체어 이동에만, 오른손은 오직 전기 봉 접촉 판정에만 반응한다 — 두 입력이 서로의 로직을 건드리지 않는다(코드 경로 분리 확인, 9장 "왼손 휠체어·오른손 전기 봉 입력 분리" 선행 검증).
- [ ] 1초 간격 미만으로 빠르게 여러 번 전기 봉 접촉이 발생해도(스펙은 휠체어에만 1초 쿨다운을 명시하고 전기 봉에는 쿨다운이 없음) 각 접촉이 모두 개별 사용으로 집계되는지, 아니면 중복 트리거 방지가 필요한지 확인하고 설계 의도를 보고서에 명시한다(스펙에 명시되지 않은 디테일이므로 판단 근거를 남긴다).
