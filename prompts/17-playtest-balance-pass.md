# 17. 수동 플레이테스트와 밸런스 조정 루프

## 목표

16번의 자동 시뮬레이션이 잡을 수 없는 "느낌" — 밀기의 타격감, 아이가 바보처럼 보이는 순간, 서사 타이밍, VR에서의 실제 불편함 — 을 사람이 직접 플레이하며 찾아내고, `GameBalanceConfig`(02번)의 값만 조정해서 고친다. 이 프롬프트는 **일회성이 아니라 반복 루프**로 설계되어 있다 — 완료 조건을 통과해도 이후 새로운 빌드가 나올 때마다 다시 수행할 수 있다.

## 선행 조건

16-simulation-and-automated-testing.md 완료 (수치적으로는 이미 안전하다는 전제 위에서 느낌을 다듬는 단계).

## 참고 스펙 섹션

`docs/spec.md` 1장(핵심 감정), 4.4(수치 변화와 공정성 — 특히 "한 회차에 스트레스를 크게 낮출 방법을 방마다 최소 2개"), 9.4 마지막 항목("L=100이 가능한지 플레이테스트 후 수치 조정").

## 구현 지시사항

1. **플레이테스트 세션 템플릿을 만든다** (`docs/playtest-log-template.md`, 새 파일): 매 세션마다 기록할 항목 — 날짜, 빌드 버전/커밋, 플레이 스타일(관찰만/적극 개입/강제 유도 등), 소요 시간, 체감 문제점, 수정 여부.
2. **최소 3가지 플레이 스타일로 전체 회차를 직접 플레이한다:**
   - **관찰자형:** 도구를 거의 쓰지 않고 지켜만 본다. 1장 "핵심 감정"이 실제로 느껴지는지, 지루하지 않은지 확인.
   - **과보호형:** 성과 물품 쪽으로 반복적으로 강하게 유도한다. 07번 강제/반복훈련/순응이 "압박감 있게" 느껴지는지, 너무 가혹하거나 너무 쉽게 뚫리지 않는지.
   - **반항 유발형:** 반항·비행 물품을 적극적으로 방문시키고 R을 높게 유지한다. 10번 비행·흡연 이벤트, 12번 조폭 엔딩까지 실제로 도달해 연출이 의도대로 느껴지는지.
3. **각 세션에서 다음을 구체적으로 평가한다:**
   - 사랑의 매로 밀 때의 타격감(물리적 반응 속도, 감전 연출의 과장/부족).
   - 서사 이벤트(종이비행기 사건, "저쪽에 가 보고 싶어" 대사, 30초 기다림 이벤트)의 타이밍이 부자연스럽지 않은지.
   - 엔딩 카드에 표시되는 "결정적 경험 3개"가 실제로 플레이어가 기억하는 순간과 일치하는지(알고리즘이 고른 것과 사람이 꼽는 것이 다르면 12번의 선정 기준을 조정).
   - 각 방에서 "스트레스를 크게 낮출 방법 최소 2개"가 실제로 눈에 띄고 매력적인지(4.4 요구사항 — 너무 묻혀 있으면 안 됨).
4. **발견한 문제는 코드 로직을 바꾸지 말고 먼저 `GameBalanceConfig` 수치 조정으로 해결을 시도한다.** 로직 자체의 결함(버그)이면 해당 원본 프롬프트(예: 07번 로직 버그면 07번 코드)를 고치되, 고친 뒤에는 16번 시뮬레이션을 다시 돌려 회귀가 없는지 확인한다.
5. **L=100 도달 가능성 점검 (9.4 마지막 항목):** 16번 시뮬레이션에서 이미 확인했겠지만, 사람이 직접 관계 중심 플레이(저녁식탁/편지/대화 등 관계 태그 물품 집중 방문)로도 L=100에 자연스럽게 도달할 수 있는지 확인한다. 너무 어렵거나 너무 쉽다면 관계 태그 물품들의 L 수치를 조정한다.
6. **조정 내역 기록:** `GameBalanceConfig`에서 바꾼 값마다 "이전 값 → 새 값, 이유, 날짜"를 `docs/playtest-log-template.md` 기반의 실제 로그 파일(`docs/playtest-logs/`)에 남긴다. 밸런스는 한 번에 완벽해지지 않으므로 변경 이력을 추적 가능하게 하는 것이 중요하다.

## 완료 조건 (Acceptance Criteria)

- [ ] 3가지 플레이 스타일 각각 최소 1회 전체 완주(45~60분) 기록이 `docs/playtest-logs/`에 남아 있다.
- [ ] 각 세션에서 발견한 문제점과 그 조치(수치 조정 또는 로직 수정) 내역이 기록되어 있다.
- [ ] 수치 조정이 발생했다면 16번 시뮬레이션을 재실행해 9.4~9.8 체크리스트가 여전히 전부 통과함을 확인했다.
- [ ] 각 방에 스트레스를 크게 낮추는 방법이 최소 2개씩 체감상으로도 존재한다.
- [ ] 관계 중심 플레이로 L=100 도달이 확인되었다(또는 확인되지 않아 조정한 뒤 재확인했다).

## 보고

3개 세션의 요약, 발견한 문제와 조치 목록, `GameBalanceConfig` 변경 이력, 재실행한 시뮬레이션 결과를 보고한다. 이 단계 이후 추가 플레이테스트가 필요하면 같은 템플릿으로 세션을 반복한다(이 프롬프트를 다시 실행).
