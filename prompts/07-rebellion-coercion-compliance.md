## 구현 지시사항

### 4.5 반항 수치 R

1. `StatType.Rebellion`에 이미 02번에서 자리가 있다. 초기값 0(다른 스탯과 다름 — `GameBalanceConfig`에 `rebellionInitialValue = 0` 별도 필드로 명시). 방을 넘어가도 누적, 100 초과분은 버림(clamp는 `StatSystem`이 이미 처리).
2. **★ 물품 R 증가의 "최초 방문만" 규칙:** `ItemEffectApplier`(05번)가 이미 "최초 방문만 효과 적용"을 보장하므로, ★ 물품의 R 효과도 같은 `statDeltas`에 포함시키면 자동으로 이 규칙을 만족한다. 다만 ★ 물품은 `ItemDefinition.isExtreme = true`이고 효과 한도가 ±25라는 점을 `ItemEffectApplier`의 clamp 로직에 반영한다(일반 물품 ±12, ★ 물품 ±25 — `ItemDefinition.isExtreme` 플래그로 분기).
3. **강제 유도 판정:** `CoercionDetector` (순수 C# 클래스)를 만든다.
   - 입력: 초파리가 어떤 `ItemSlot`(I 또는 H가 +5 이상인 물품만 대상)에 실제로 입장(= `OnFirstVisit` 트리거)한 시각, 그 이전 10초 동안 발생한 모든 `ToolUsed` 이벤트(방향, 강도, 대상 방향이 그 아이템 쪽이었는지).
   - "그 물품 쪽으로 밀었다"의 판정: 접촉 시점의 밀림 방향 벡터와, 접촉 지점→아이템 위치 벡터의 내적(또는 각도)이 일정 임계값 이내면 "해당 방향으로 미는 중"으로 간주한다. 임계값은 `GameBalanceConfig.coercionDirectionToleranceDegrees`로 노출(기본값 예: 45도 — 플레이테스트로 조정 가능하다는 점을 주석에 남긴다).
   - 10초 안에 휠체어 밀기만 있었으면: 방문 확정 시 `R += 2, S += 1` (물품 기본 효과와 별도의 추가 적용, 1회만).
   - 10초 안에 전기 봉(사랑의 매) 접촉이 하나라도 있었으면(휠체어 밀기와 섞였어도): `R += 5, S += 3` (전기 봉 효과만 적용, 휠체어 쪽과 중복 적용하지 않음).
   - 전기 봉 접촉 자체의 즉시 효과: 접촉이 발생한 "그 순간"(물품 방문 여부와 무관)에 기존 4.3 기본 스트레스 공식에 **더해서** `S += 2`를 즉시 적용한다. 이건 04번 `ToolUsageTracker`의 델타 계산 뒤에 덧붙이는 추가 텀이므로, 04번 코드를 고쳐서 "접촉 소스가 전기 봉이면 +2 추가"를 넣는다. 휠체어의 유효 접촉과 전기 봉 접촉은 별개 이벤트로 기록한다(스펙 4.5).
4. **반복 훈련 판정:** `RepeatedTrainingTracker` (순수 C# 클래스, 방 단위로 리셋).
   - 같은 방에서 I 또는 H가 +5 이상인 물품의 "첫 방문" 횟수를 센다(= 다른 물품들끼리의 누적, 같은 물품 재방문은 세지 않음 — `ItemEffectApplier`가 이미 재방문을 구분하므로 그 이벤트만 구독).
   - 3번째 방문부터: 방문마다 `R += 4, S += 3` 추가. 해당 방문이 동시에 강제 훈련 판정이었다면 3번의 효과와 이 효과를 **모두** 더한다.
   - 한 방에서 이 추가 효과는 최대 3회까지만 적용(즉 4번째, 5번째... 성취 물품 방문부터는 반복 훈련 추가 효과가 더 늘지 않음 — 하지만 R/S 누적값 자체는 유지되고 다음 방까지 넘어간다).
5. **회복 행동:** `RelationshipState`/`StatSystem`에 "도구 미사용 60초 경과" 이벤트가 이미 04번에 있다(T+1 로직과 같은 타이머 재사용 가능). 이 60초마다 `R -= 2`, 방당 최대 `-8`. 방 진입 시 누적 카운터 리셋.
6. **청소년기 이벤트 연계용 플래그:** R≥35일 때 "관련 대사 증가" 플래그를 UI/대화 시스템이 읽을 수 있게 `GameState`에 노출(`IsHighRebellionDialogue => Rebellion >= 35`). R≥60일 때 "청소년기 종료 특별 이벤트 확정" 플래그(`IsFlightSmokeEventTriggered`)도 노출 — 실제 이벤트 재생은 10번 프롬프트(청소년기 방)에서 구현.

### 4.6 지속적인 휠체어·사랑의 매 사용과 방향 순응

7. **`ComplianceStateMachine` (순수 C# 클래스):** 상태 = `Free`(자유 이동), `AvoidingTool`(04번의 12초 회피), `Complying`(순응 중).
   - 최근 30초 윈도의 "같은 방향 유효 접촉 누적 점수"를 추적. 휠체어 밀기 = 1점, 전기 봉(사랑의 매) 접촉 = 2점. 접촉 간 최소 1초 간격만 카운트(그보다 빠른 접촉은 무시, 중복 집계 방지).
   - 방향이 "반대"로 바뀌거나 10초 동안 추가 접촉이 없으면 누적 점수를 0으로 리셋. "방향"은 04번 `PushResolver`가 계산한 밀림 방향 벡터를 8방位 또는 연속 각도로 비교해 "반대"를 판정한다(각도 임계값은 `GameBalanceConfig`에 노출).
   - 임계점: `Rebellion < 70`이면 6점, `Rebellion >= 70`이면 8점에서 `Complying`으로 전환. `Rebellion`이 100이어도 8점 누적 시 반드시 전환(예외 없음 — 테스트로 반드시 확인).
   - `AvoidingTool` 상태 중에 이 임계점에 도달하면 즉시 `Complying`으로 전환(04번에서 만들어 둔 `ForceEndAvoidance()`를 여기서 호출).
8. **`Complying` 상태 동작:**
   - 8초 지속. 같은 방향으로 유효 접촉이 이어지면 8초 타이머가 그때마다 갱신(= 리셋되어 다시 8초).
   - 이 상태 동안 `FlyAgent`는 미는 방향 쪽의 가장 가까운 유효 NavMesh 지점으로 이동(03번 NavMesh 활용). 벽/가구에 막히면 그 방향에서 가장 가까운 통행 가능 지점으로 대체 이동(NavMesh의 `CalculatePath` 실패 시 fallback 지점 탐색 로직 필요).
   - 상호작용 영역(1.2m) 도착 + 2초 머묾 → 해당 `ItemSlot`의 1회 효과 적용(이미 방문한 적 있으면 적용 안 함 — 기존 규칙 유지) + "강요당한 방문" 플래그를 이벤트 로그에 남김 + `Complying` 상태 해제.
   - 상태 해제 후 도구 사용이 멈추면 `Free`로 복귀해 자율 탐색 재개(영구 선호 고정 아님).
9. **대가 적용:**
   - 임계점 도달 순간(1회): `S += 4, R += 6`.
   - `Complying` 상태 중 추가 유효 접촉마다: `S += 1, R += 2`.
   - 이 값들은 4.3 기본 공식과 4.5 전기 봉/강제훈련 효과에 **추가로** 더해진다. 모든 적용 후 0~100 clamp.
10. EditMode 테스트 (`Assets/Tests/EditMode/RebellionComplianceTests.cs`) — 9장 9.7, 9.8의 검증 항목을 그대로 테스트 케이스화한다:
    - 휠체어 밀기로 유도한 강제 훈련과 전기 봉으로 유도한 강제 훈련의 R/S 증가량이 각각 명세와 일치.
    - 같은 물품에 여러 번 도구를 써도 방문 추가 효과는 1회만 적용되고, 전기 봉 접촉 자체의 즉시 S+2는 사용 횟수만큼 반복 적용되는지.
    - 서로 다른 I/H 물품 3개째부터 반복 훈련 증가가 적용되고, 최대 3회로 제한되는지.
    - R=100 상태에서도 휠체어 밀기 8회(또는 전기 봉 4회, 2점×4=8점)로 순응이 발생하는지.
    - 방향을 바꾸거나 10초 경과 시 누적이 리셋되는지.
    - 순응 중 벽에 막혀도 대체 지점으로 이동이 계속되는지(간이 NavMesh mock 또는 PlayMode 테스트로 보완).
    - 강제 도착 후 물품 효과가 정확히 1회만 적용되는지.
    - R≥35, R≥60 플래그가 올바른 시점에 켜지는지.
