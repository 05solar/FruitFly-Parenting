# 13. 초파리 뇌지도(커넥톰) 시각화 — 실험 빌드

## 목표

스펙 7장을 구현한다. **이것은 본편 VR 플레이 루프와 분리된 실험/연출 빌드다.** 본편(05~12번)의 성능이나 정확성에 영향을 주지 않도록 별도 씬/별도 빌드 타깃으로 작업한다.

## 선행 조건

12-middleage-and-endings.md 완료 (전체 게임 루프가 완결된 상태). 이 프롬프트는 본편 완성 후 착수하는 것을 권장하지만, 독립적인 실험 빌드이므로 08번(선호 학습) 완료 후 병행 착수도 가능하다.

## 참고 스펙 섹션

`docs/spec.md` 7장(초파리 뇌지도 활용 설계) 전체, 10장(자료와 사실 관계)의 [1][2][3] 출처.

## 구현 지시사항

1. **데이터 명세 문서 작성 (`docs/connectome-data-spec.md`, 새 파일):** 이번 단계에서 실제로 사용할 FlyWire 데이터의 버전(예: FAFB 데이터셋의 특정 release), 선택한 뉴런/영역 집합, 원본 연결 가중치를 게임 연출용 값으로 변환하는 규칙, 출처 URL([1][2][3])을 고정해서 기록한다. **이 문서 없이 비주얼 구현에 들어가지 않는다** — 7장이 요구하는 "사용할 데이터 버전, 선택 뉴런·영역, 가중치 변환 규칙, 출처를 데이터 명세에 고정한다"는 요구사항을 지키기 위함이다.
2. **라이선스 확인:** FlyWire Codex에서 다운로드하는 정적 데이터/주석과, 만약 학술 도판·3D 메시를 그대로 쓴다면 그 자료의 라이선스를 각각 확인하고 `docs/connectome-data-spec.md`에 출처 표기 문구를 그대로 기록한다. 라이선스가 불명확한 자료는 사용하지 않고 자체 제작한 추상 시각화(노드-엣지 그래프 등)로 대체한다.
3. **오프라인 전처리 파이프라인:** FlyWire Codex에서 받은 원본 데이터(수만~수십만 뉴런 규모)를 실시간 로드하지 않는다(7장 "VR 본편에서는 오프라인 전처리된 작은 요약 그래프만 로드하고 대규모 커넥톰 원본을 실시간 실행하지 않는다"). Unity 외부(Python 스크립트 등, 이 저장소의 `tools/` 폴더에 별도 작성)에서 "감각 입력 → 연합/학습 관련 영역 → 행동 출력" 경로의 선별된 뉴런/영역만 추출해 작은 JSON/바이너리 요약 그래프로 변환한다. 이 전처리 스크립트와 그 입출력 포맷을 `docs/connectome-data-spec.md`에 함께 기록한다.
4. **Unity 시각화 (`ConnectomeViewer`):** 전처리된 요약 그래프를 로드해 노드-엣지 3D 그래프로 렌더링하는 별도 씬(`Assets/_Project/Scenes/Experimental_ConnectomeViewer.unity`)을 만든다. 복도 사이 "신경망 모양을 모티브로 한 기억 연출"(7장 1번 계층)에 쓸 수 있는 가벼운 버전도 함께 만들되, 본편 복도(06번 `CorridorShell`)에 통합할지는 별도 결정으로 미루고 지금은 독립 데모로만 완성한다.
5. **출처 표기 UI:** 시각화 화면 어딘가에 "FlyWire Consortium, Nature 2024" 등 출처와 "이 시각화는 창작된 게임 연출이며 실제 초파리의 행동을 재현하지 않습니다"라는 고지 문구를 항상 표시한다(7장의 "실제 커넥톰에서 도출한 관계와 창작한 게임 규칙을 UI·문서에서 구분한다" 요구사항).
6. **행동 계층과의 명확한 분리 재확인:** 08번에서 만든 `ItemChoiceModel`(softmax 기반 선호/회피)은 이 커넥톰 시각화와 **데이터상으로 연결되지 않는다**(= `ConnectomeViewer`가 `ItemChoiceModel`의 내부 수치를 읽어서 보여주는 것은 가능하지만, 반대로 커넥톰 원본 그래프가 `ItemChoiceModel`의 확률을 실시간으로 결정하지 않는다). 이 분리를 코드 상에서도 강제한다 — `ConnectomeViewer`는 `Assets/_Project/Scripts/Fly/` 네임스페이스에 의존하지 않고 독립 모듈로 작성한다.
7. **(선택) 연구형 비교 실험 뼈대:** 7장 "향후 연구형 확장" 문단에 언급된, 같은 방·같은 난수 시드에서 "제한된 회로 기반 모델"과 "단순 태그 정책"을 비교하는 실험은 이번 단계에서 전체 구현까지 하지 않아도 되며, 인터페이스(두 정책이 같은 `IFlyDecisionPolicy` 인터페이스를 구현하도록 08번 `ItemChoiceModel`을 추상화)만 만들어 두고 실제 회로 기반 모델 구현은 범위 밖으로 명시한다.

## 완료 조건 (Acceptance Criteria)

- [x] `docs/connectome-data-spec.md`가 존재하고 데이터 버전/선택 영역/변환 규칙/출처가 모두 기록되어 있다.
- [x] 라이선스가 불명확한 자료가 프로젝트에 포함되어 있지 않다(사용한 모든 외부 자료의 출처/라이선스가 명세서에 1:1로 대응).
- [x] `Experimental_ConnectomeViewer` 씬이 본편 씬들과 별도로 존재하며, 본편 빌드(05~12번 결과물)의 빌드 크기/로드 시간에 영향을 주지 않는다(본편 빌드에서 이 씬/대용량 데이터가 제외되는지 빌드 설정 확인).
- [x] 출처/고지 문구가 시각화 화면에 항상 보인다.
- [x] `ConnectomeViewer`와 `ItemChoiceModel`이 단방향 의존(뷰어→정책 읽기 전용, 역방향 없음) 구조임을 코드 검색으로 확인한다. 구현은 양방향 참조가 모두 없는 완전 독립 구조다.

검증: Python 9/9, EditMode 5/5, PlayMode 1/1 및 독립 Windows 빌드. 본편 자산/DLL 제외는 **12단계 커밋 설정 + 13단계 파일**의 실제 빌드로 확인했다. 현재 사용자 Meta XR 설정은 별도 OpenXR 검증 오류가 있어 보존했으며, [보고서](../docs/tech-stack.md#16-13-커넥톰-독립-시각화)에 구분 기록한다.
