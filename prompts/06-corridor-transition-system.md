# 06. 복도와 방 전환 시스템

## 목표

05번에서 placeholder로 남겨둔 "복도"를 스펙 2장의 실제 복도 연출로 교체한다. 이후 모든 방(09, 10, 11, 12)은 이 복도 시스템을 그대로 재사용한다.

## 선행 조건

05-infant-room-vertical-slice.md 완료.

## 참고 스펙 섹션

`docs/spec.md` 2장 전체(특히 복도 구간 구성), 5.2~5.5의 "복도 1~4" 문단, 8장(편안함·소리 기준).

## 구현 지시사항

1. **`CorridorShell` 프리팹:** 폭 4m, 길이 12~16m 통로. 구간 3분할 — 진입 측 4m(회상 구간), 중앙 6m(한 문장 내레이션 구간), 출구 측 4m(다음 시기 실루엣 구간). 길이가 12m면 중앙 구간을 4m로 비례 조정하되, 세 구간의 비율(약 1/3씩)을 유지한다.
2. **`CorridorRecapController`:** 이전 방에서 실제로 방문했던 물품 중 2~3개를 골라(랜덤 또는 "가장 수치 변화가 컸던 것" 우선 — 설계 판단을 내리고 보고서에 근거를 남긴다) 벽에 사진/실루엣으로 띄운다. `GameState`의 이번 방 이벤트 로그(02번에서 만든 `EventLogEntry` 리스트)를 읽어서 생성하므로, 하드코딩된 물품이 아니라 실제 플레이 기록에서 가져와야 한다.
   - 아이의 한마디(대사 텍스트)와 "부모의 개입 흔적"(예: 개입 횟수가 많았으면 흔들린 사진, 적었으면 또렷한 사진 — 8장의 "색 외에 모양으로 수치 표현" 원칙에 맞춰 수치를 직접적인 숫자 대신 비주얼 변형으로 암시)을 함께 표시한다.
   - 이전 물품을 피하게 했는지(반감 생긴 물품)는 복도 벽 사진에서 흐릿하게/금 간 효과로 표현한다(5.2 복도 1 설명).
3. **중앙 내레이션 구간:** 한 문장짜리 텍스트(예: "아이는 말할 수 있게 되었다") + 자막(8장 접근성 기준 — 항상 자막 동반). 다음 방으로 갈수록 이 문장의 주체가 "부모의 시선"에서 "아이의 시선"으로 바뀌도록 템플릿을 설계한다(3장 월드의 이야기 — "부모의 취향에서 아이의 취향으로").
4. **출구 측 실루엣 구간:** 다음 방의 테마를 암시하는 실루엣(색/조명만 바뀐 간단한 모양, 디테일 아트는 나중). 복도 끝 문이 다음 방 로드 완료 시 열린다.
5. **`RoomTransitionController`:** 05번의 "방 종료 트리거"를 이 컨트롤러로 일반화한다. 시퀀스: 현재 방 페이드 아웃(0.5초+) → 복도 입장 → 회상/내레이션/실루엣 순서로 플레이어가 왼손 스틱으로 휠체어를 직접 운전해 통과(강제 자동 이동 없음, 8장 "자동 카메라 이동 금지" 준수) → 복도 끝 도달 시 다음 방 페이드 인. 씬 전환이 아니라 `tech-stack.md`에서 정한 "단일 영속 씬 + 컨테이너 활성화" 방식을 사용해 로딩 끊김이 없게 한다.
6. **소리 전환 (8장):** 이전 방의 배경음 중 한 소리가 복도 진입부에 메아리처럼 남아 서서히 사라지고, 복도 중반부터 다음 방 소리가 서서히 커지는 크로스페이드를 구현한다.
7. 복도는 성장 방 사이에만 존재한다는 규칙(2.5)을 지키기 위해, `RoomTransitionController`가 "프롤로그→영유아", "영유아→아동", ..., "청년→중년" 전환에만 호출되도록 구성한다.

## 완료 조건 (Acceptance Criteria)

- [x] 영유아 방 종료 → 복도 → (placeholder) 다음 방 진입까지 끊김/로딩 없이 자연스럽게 이어진다.
- [x] 복도에 표시되는 회상 사진/대사가 실제 이번 방 플레이 로그에서 동적으로 생성된다(하드코딩 금지 — 서로 다른 조작의 2회 실행과 GPU 캡처 시각 비교로 확인).
- [x] 복도를 지나는 동안 플레이어 시점이 강제로 전진하지 않는다(왼손 스틱으로 사용자가 직접 휠체어를 운전해 이동하며, 순간이동이나 자동 전진은 없음).
- [x] 복도 폭 4m 안에서 0.8m 휠체어가 회전/통과하는 데 무리가 없다(03번에서 만든 휠체어 프록시로 재확인).
- [x] 소리 크로스페이드가 급격한 끊김 없이 재생된다.
- [x] 복도 진입/퇴장 시 02번 `SaveSystem.SaveCheckpoint`가 호출된다(진입 `corridor_start`, 퇴장 `corridor_end`, 다음 방 `room_enter`로 구분).
