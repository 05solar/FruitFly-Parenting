# 초파리 육아 VR 게임 — 행복한 초파리 만들기

VR 육아·관찰 시뮬레이션 게임. 플레이어는 초파리 아이의 보호자가 되어 시대별 방을 거치며 자유롭게 행동하는 아이를 지켜보거나 '사랑의 매'로 방향을 유도한다. 개입의 빈도와 강도가 아이의 성향과 부모-자녀 관계, 그리고 14가지 엔딩으로 돌아온다.

## 이 저장소의 구조

```
docs/
  spec.md             # 기획 명세서 (단일 진실 소스 — 모든 구현 판단의 기준)
  tech-stack.md       # Unity + XR Interaction Toolkit 기술 스택과 프로젝트 규칙
prompts/
  README.md           # 단계별 구현 프롬프트 사용 가이드
  01-17...            # 번호 순서대로 실행할 구현 프롬프트 17개
```

Unity 프로젝트 본체는 이 루트의 `Assets/`, `Packages/`, `ProjectSettings/`에 있다.

## 기술 스택 요약

- **엔진:** Unity (URP), XR Interaction Toolkit + OpenXR
- **1단계 타깃:** PCVR (개발/반복 속도 우선)
- **2단계 타깃:** Meta Quest 스탠드얼론 (15번 프롬프트에서 최적화)

자세한 내용은 [`docs/tech-stack.md`](docs/tech-stack.md) 참고.

## 시작하는 법

1. [`docs/spec.md`](docs/spec.md)를 읽고 게임 전체 설계를 이해한다.
2. [`prompts/README.md`](prompts/README.md)의 사용법을 따라 `prompts/01-project-setup.md`부터 순서대로 Claude Code에 지시한다.
3. 각 프롬프트의 "완료 조건"을 전부 통과해야 다음 번호로 넘어간다. 자동 테스트(EditMode/PlayMode)와 16번의 헤드리스 시뮬레이션으로 수치·엔딩·경계 조건을 검증하고, 17번에서 사람이 직접 플레이하며 느낌을 다듬는다.

## 현재 진행 상태 (2026-11-23)

- Unity `6000.6.2f1`에서 02 핵심 데이터, 03 방·자율 이동, 04 휠체어·전기 봉·스트레스/신뢰 모델, 05 영유아 방, 06 복도·전환 시스템, 07 반항·강제훈련·순응, 08 태그 선호·회피 학습, 09 아동기 방을 구현했다. 다음 구현 단계는 10 청소년기 방이다. 실제 HMD 수동 검증은 아래와 같이 남아 있다.
- URP 렌더러를 모든 품질 레벨에 연결했다. 실제 GPU 렌더링 테스트에서 빈 화면·분홍색 셰이더 오류가 없음을 확인했다.
- `RoomShell.prefab`은 저장된 `RoomShellNavMesh.asset`을 참조한다. 초파리는 가구 중심 대신 상호작용 영역 내 도달 가능한 바닥 점으로 이동한다.
- `00_Bootstrap`, `03_RoomShellTest`에 XR Origin을 포함한 `WheelchairRig.prefab`을 배치했다. 왼손 스틱이 XRI Continuous Move/Turn을 구동하고 오른손에는 버튼 없이 접촉하는 전기 봉이 고정된다. 휠체어 폭은 0.8m이며 가감속을 적용했다.
- 범퍼는 이동 중에만 1초 간격으로 약한 밀기를 적용한다. 전기 봉은 접촉 중 중복을 제거하고 완전히 뗐다 다시 대면 즉시 별도 접촉으로 센다. 두 소스의 스트레스·신뢰·최근 60초 집계를 공유하고, 연속 4회 접촉 시 12초 동안 밀림에 저항한다. [04 구현 및 검증 보고](docs/tech-stack.md#7-04-휠체어전기-봉접촉-모델)를 참고한다.
- `01_Infant`를 기본 시작 씬으로 등록했다. 물품 9개 최초 방문 효과·재방문 대사, 초반 90초 개입 제한, 8분 문 개방, 10분 새 효과 종료, 체크포인트 저장을 연결했다. 관찰 후 출구까지 운전한 자동 플레이스루는 게임 시간 약 **8분 17초**, 개입 없이 서로 다른 물품 **9개**를 경험했다. [05 구현 및 검증 보고](docs/tech-stack.md#8-05-영유아-방--첫-손길)를 참고한다.
- 06에서 복도 임시 화면을 **폭 4m·길이 14m의 실제 복도**로 교체했다. 이번 방의 실제 방문 3개와 아이 대사, 개입·밀려남의 흔적을 표시한다. 회상→내레이션→실루엣 구간을 왼손으로 운전하고, 같은 씬의 다음 방으로 진입한다. 카메라 강제 이동 없이 실제 시간 0.75초 페이드와 소리 크로스페이드를 적용했다. [구현·검증·스크린샷](docs/tech-stack.md#9-06-복도와-방-전환)을 참고한다. 09에서 아동기 게임플레이와 복도 2를 연결했다.
- 07에서 반항 R, ★ 물품 최초 효과 ±25, 방향에 따른 강제 훈련, 서로 다른 성취 물품 3·4·5번째의 반복 훈련, 60초 관찰 회복을 연결했다. R=100에서도 전기 봉 4회로 순응하며, 도달 가능한 경로로 이동한 뒤 2초 방문 완료 또는 8초 만료 시 자율 이동으로 돌아간다. 청소년기 특별 이벤트는 10번에서 출구 개방 시 R을 확정해 사용하는 API까지 준비했다. [상태 전이·수치·각도·검증 보고](docs/tech-stack.md#10-07-반항강제반복-훈련방향-순응)를 참고한다.
- 08에서 실제 저지·방문 결과를 태그 기억으로 저장하고 자율 선택에 반영했다. 시기별 균등 탐색 하한을 유지해 회피가 높아도 접근을 금지하지 않는다. 같은 시드 20,000회 비교에서 놀이 선택은 개입 없음 5,031회 / 이전 방에서 반복 저지 3,100회였다. **F8**로 선택 이유·확률·시드를 볼 수 있으며 Windows 개발/릴리즈 플레이어의 표시·비표시를 각각 검증했다. [학습 로그·확률 공식·빌드 검증](docs/tech-stack.md#11-08-태그-선호회피-학습)을 참고한다.
- 09에서 하나의 연결된 방에 교실·놀이터와 **일반 8개/★ 4개 물품**을 배치했다. ★ 물품은 2초 망설임 후 체류 효과를 적용하며, **3분 30초의 종이비행기 사건**은 당시 방문·신뢰에 따라 세 장면으로 나뉜다. 복도 2 회상과 영유아·아동기 종료 Stress 저장을 연결했다. [좌표·분기·종료 기록 보고](docs/tech-stack.md#12-09-아동기-방--놀이터와-첫-약속)를 참고한다.
- EditMode **148/148**, PlayMode **43/43** 통과(실패·생략 0개). 09의 모델 검사 23개와 씬 통합 검사 7개를 포함하며 기존 02~08의 회귀 검사도 통과했다. 아동기 NavMesh는 **148개 삼각형 / 연결 영역 1개**, 물품 슬롯 12개 모두 접근 가능하다. 기존 방 쉘은 116개 삼각형 / 연결 영역 1개다. Windows 개발·릴리즈 플레이어 빌드와 실행은 08에서 검증했으며, 09는 에디터 모델·씬 통합 검증을 수행했다.
- 이 PC에는 OpenXR 런타임이 등록되어 있지 않아 HMD 양안 출력·실제 컨트롤러 추적을 검증하지 못했다. Android Build Support도 설치되지 않아 Quest 빌드는 미검증이다. 이 항목들은 01단계의 실기기 검증으로 남아 있다.

Unity에서 `Assets/_Project/Scenes/01_Infant.unity`를 열고 Play하면 영유아 방을 시작한다. 문이 열리면 왼손으로 출구와 복도를 운전해 아동기 방으로 이동하고, 이후 복도 2와 청소년기 임시 공간까지 진행할 수 있다. 아동기부터 시작하려면 `03_Childhood.unity`를 연다. 헤드셋이 없으면 Game 뷰의 고정된 앉은 시점으로 관찰할 수 있으며, 실제 출구 통과에는 왼손 컨트롤러 입력이 필요하다. `03_RoomShellTest.unity`는 기존 방·접촉 검사용으로 유지한다. 자동 테스트는 에디터를 닫은 뒤 프로젝트 루트에서 실행한다:

```powershell
.\scripts\Test-Project.ps1
```

결과는 `Logs/editmode-results.xml`, `Logs/playmode-results.xml`에 저장한다. 영유아 방의 물품별 최초 방문 로그는 `Logs/infant-first-visits.txt`, 플레이스루 시간은 `Logs/infant-playthrough.txt`, 화면 캡처는 `Logs/infant-room.png`와 `Logs/infant-corridor.png`다. 기존 방 캡처는 `Logs/room-render.png`에 저장한다. `Logs/`는 Git에서 제외한다. 설정 복구 방법과 검증 범위는 [기술 스택 문서](docs/tech-stack.md#6-현재-설정과-재검증)를 참고한다.

복도 재생 기록은 `Logs/corridor-playthrough.txt`, 서로 다른 두 회차의 원본 로그는 `Logs/corridor-recap-a.json`, `Logs/corridor-recap-b.json`이다. 검증한 복도·회상·다음 방 스크린샷은 `docs/images/`에도 보관한다.

## 진행 단계 한눈에 보기

| 단계 | 내용 |
|---|---|
| 01~03 | 프로젝트 셋업, 핵심 데이터 아키텍처, 방 쉘/NavMesh |
| 04 | 도구(사랑의 매)와 기본 스트레스 공식 |
| 05~06 | 영유아 방 수직 시연, 복도/전환 시스템 |
| 07~08 | 반항·강제훈련·순응 상태머신, 선호/회피 학습 |
| 09~12 | 아동·청소년·청년·중년 방, 14개 엔딩 분기 |
| 13 | 초파리 뇌지도(FlyWire 커넥톰) 시각화 — 별도 실험 빌드 |
| 14~15 | VR 편안함/접근성 감사, Quest 최적화 |
| 16~17 | 자동 시뮬레이션 전수 검증, 수동 플레이테스트·밸런스 |

게임 수치·태그·서사·엔딩 규칙은 이 기획을 위해 창작된 것이며, FlyWire 커넥톰 데이터(7장)는 연출·시각화 참고 자료로만 쓰이고 실제 초파리 행동이나 인간 발달을 재현한다고 주장하지 않는다.
