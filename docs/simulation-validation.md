# 16단계 자동 시뮬레이션 검증

아래 결과는 초반 90초 도구 대기가 있던 당시 규칙의 기록이다. 2026-11-25 후속 요청으로 이 대기를 제거했으며, 현재 플레이어와 시뮬레이션 정책 모두 방 입장 직후 개입할 수 있다. 이 변경 후 전체 엔딩 분포 배치는 다시 실행하지 않았다.

2026-11-25, Unity 6000.6.2f1. 최종 배치 **3,494회**, 각 회차를 같은 정책·시드로 다시 실행한 **총 6,988회**가 129.50초에 끝났다. 씬 로드 0회, 14개 엔딩 도달, 수치·중복 효과 위반 0건, 전체 이벤트 로그까지 재현 일치율 100%다. [기계 판독 보고서](reports/step16-validation.json).

## 실행과 산출물

Unity Play 모드를 종료하고 `Fruit Fly Parenting > Run 16 Headless Simulation`을 실행한다. 에디터를 닫고 커맨드로 실행할 수도 있다.

```powershell
.\scripts\Run-Simulation.ps1
python tools/verify_simulation_reports.py SimulationReports
```

이미 열린 프로젝트를 배치 실행하지 않도록 `-ProjectPath`로 별도의 복사본을 지정할 수 있다. `-Count`는 Passive/Random/Aggressive **각 정책의 시드 수**이며 기본 1,000이다. `-Probe -Count 100`은 탐색용 소규모 실행으로, 전체 완료 조건 검사가 아니다.

`SimulationReports/`에는 `summary.json`, 모든 회차의 최종 수치·SHA256을 담은 `runs.csv`, 전체 이벤트를 담은 `runs.jsonl`, 엔딩별 정책·시드 증거 JSON, 독립 검사 결과 `verification.json`이 생성된다. 원본 보고서는 Git에서 제외한다. 기존 엔딩 증거 파일은 다음 탐색의 시작 시드로만 사용하며, 저장된 결과나 수치를 주입하지 않고 새 초기 상태에서 반드시 다시 실행한다. 새 환경에서 증거가 없으면 엔딩별 시드를 탐색하므로 시간이 더 걸린다.

## 구현과 해석 범위

`SimulationRunner`는 씬·렌더러·XR·NavMesh에 접근하지 않는 C# 실행기다. 실제 데이터 에셋과 `GameState`, `ItemChoiceModel`, `ToolUsageTracker`, `ComplianceStateMachine`, `CoercionDetector`, `ItemDwellTracker`, `ItemEffectApplier`, `YoungAdultItemEffects`, `EndingEvaluator`를 재사용한다. 순수 `ContactModel`을 추출해 실제 `FlyContactReceiver`도 동일한 비용·회피·순응 판정을 호출한다. 가상 플레이어 정책은 수치·플래그를 직접 변경하지 않고 접촉 소스와 유도 방향만 선택한다.

정책은 무개입, 무작위 빈도·강도, 공부 방향의 강한 지속 유도, 엔딩별 목표 정책이다. 관계 엔딩 일부는 관찰 정책으로 도달하는 시드를 찾는다. 작은 식탁 정책은 5초보다 긴 간격의 휠체어 접촉으로 활동을 끊는 패턴이다. 목표 정책이 모든 시드에서 같은 엔딩을 보장하지는 않는다. 아래 빈도는 공격적 정책과 도달 사례 탐색을 포함하므로 일반 사용자의 엔딩 확률로 해석하면 안 된다.

이동은 아이템 위치 사이 거리/2.5m/s로 근사하며 NavMesh 경로 길이·장애물·플레이어가 접촉 위치까지 접근하는 과정은 생략한다. 순응의 6m 범위·방향 허용각·최근접 아이템·시간 만료·기존 자율 목표 복귀는 유지한다. 일반 밀기를 순응 이동에 중복 적용하지 않으며, 실제 상호작용 영역을 벗어난 경우에만 이탈 학습을 기록한다. 관찰 정책의 이미 확정된 체류 구간만 이벤트 단위로 건너뛴다. 게임 시간·체류·90초 관찰·도박 연출·문 열림·최종 스냅샷은 계속 계산한다. 이 결과는 실제 VR 조작감이나 실시간 45~60분 플레이 길이를 보증하지 않는다.

## 발견하여 수정한 도달 불가능 조건

기존 02/04의 신뢰 증가와 12의 히든 엔딩 조건 사이에 경로가 없었다. 초기 T=50에 네 성장 방의 최대 관찰 보상 +16을 더해도 66이며, 기존 물품의 신뢰 변화는 감소뿐이었다. 연락 재개 보상도 먼저 연락 차단 손실을 받아야 하므로 T≥70을 해결하지 못했다.

[명세 4.1](spec.md#41-상태값과-행동-로그)에 첫 자율 방문 신뢰 회복을 추가했다. 아동기 가족 식탁, 청소년기 부모와 대화, 청년기 편지를 처음 자율 방문하면 각각 **T +8**이다. 강제·순응·직전 6초 개입·재방문·효과 종료 후 방문은 보상하지 않는다. `GameBalanceConfig`에서 보상과 대상 물품을 관리하며, 로그에는 clamp 후 실제 증가량을 남긴다. 기존 초기값, L 물품 효과, 개입 비용과 엔딩 문턱은 유지했다.

`PassivePolicy`, **seed 1111**은 개입 0회로 **L=100, T=72**, 마법소녀 엔딩에 도달했다. 히든 의상은 최종 배치에서 **2,177회** 확인했다. 명세 4.6에 따라 회피 중에는 추가 **이동**을 차단하되 접촉 비용·집계는 유지하고, 순응 임계점에 도달하면 회피를 끝낸다. 16단계 프롬프트의 “입력 무시”를 비용까지 없애는 동작으로 바꾸지는 않았다.

## 실제 씬 5분 fuzz와 회귀 검사

성장 네 방에서 각각 **300초 이상**, 총 약 24,001프레임 동안 실제 FlyAgent와 휠체어를 구동했다. 무작위 약/강 접촉, 30초 개입/30초 관찰 구간, 모든 물품 접근 경로, OffMeshLink 이탈, 60초 정지, 벽/가구 겹침과 외곽 이탈을 검사했다. 청년기의 의도된 15초 활동 보호는 물리 끼임으로 오인하지 않으며 조작을 멈춘 뒤 자율 이동 재개를 함께 관찰한다.

중년기에는 원래 움직이는 FlyAgent/NavMesh 캐릭터가 없다. 배우를 새로 만들어 검사를 통과시키는 대신, 실제 휠체어가 서쪽에서 거실로 **6.25m 접근**한 뒤 착석 상태에서 회전 입력을 받는 구조를 **300초/6,000프레임** 검사했다. 이 방은 NavMesh 초파리 fuzz가 아닌 실제 엔딩 입력·물리 검사다.

EditMode **259/259** 통과. PlayMode는 전체 **76개 중 72개**가 첫 실행에 통과했고, 변경된 신뢰 보상의 이전 기대값을 사용하던 4개를 수정하여 전부 재실행·통과했다. 강화한 5분 fuzz도 재실행했다. 최종 검사 결과를 테스트 이름 기준으로 합치면 **76/76**, 생략 0개다. 원본 XML 및 병합 근거는 기계 판독 보고서에 적었다.

모델·배치 검증은 Meta XR 209/Android 설정을 보존한 `Logs/Step15Project`, 실제 PlayMode는 기존 Windows OpenXR/XRI 기준의 `Logs/Step14Project`에서 수행했다. 사용자 루트 SDK 설정을 바꾸지 않았다. 실제 HMD·프레임 성능·수동 게임 완주는 이번 자동 검증 범위에 포함하지 않는다. 기존 실행 중인 Windows 플레이어와 APK는 재빌드하지 않았으므로 이번 신뢰 보상은 다음 빌드부터 반영된다.
